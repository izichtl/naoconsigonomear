Projeto de Machine Learning

Research SLM

Modelo de linguagem pequeno, especializado em geração de estratégias e strings de busca científica, com aprendizado incremental e atualização real dos pesos.

Local-first Apple Silicon Continual Learning

1. Visão geral

Objetivo principal

Desenvolver um Small Language Model especializado em interpretar contextos de pesquisa e gerar consultas bibliográficas adaptadas às particularidades sintáticas e operacionais de diferentes bases científicas.

O modelo deverá aprender novos padrões por meio de treinamento incremental, atualizando seus próprios pesos, sem depender de RAG ou da consulta permanente aos documentos originais.

2. Funcionalidades esperadas

Interpretação

Entender o contexto, objetivo, população e critérios da pesquisa.

Geração

Produzir strings de busca com operadores booleanos, campos e filtros.

Especialização

Conhecer as diferenças entre as APIs e bases científicas.

Aprendizado

Incorporar exemplos validados mediante atualização dos pesos.

Validação

Verificar sintaxe, campos e compatibilidade das consultas.

Evolução

Receber novos exemplos e evoluir continuamente por checkpoints.

5. Aprendizado incremental

O mecanismo de aprendizado deverá permitir receber novos exemplos, transformá-los em dados de treinamento e atualizar os parâmetros do modelo. 

modelo.aprender(
    contexto="Pesquisar ferramentas de observabilidade Kubernetes",
    api="PubMed",
    resultado=[
        "Kubernetes observability tools",
        "Kubernetes monitoring platforms",
        "Kubernetes distributed tracing solutions"
    ]
)

Fluxo interno:

  1. Receber exemplo validado.
  2. Normalizar e tokenizar os dados.
  3. Calcular a função de perda.
  4. Executar backpropagation.
  5. Atualizar os pesos do modelo.
  6. Executar testes de retenção e qualidade.
  7. Salvar novo checkpoint.

O treinamento deve preservar exemplos anteriores para reduzir o esquecimento catastrófico.

6. Padrão dos documentos de treinamento

Cada exemplo deverá possuir uma estrutura padronizada, permitindo treinamento misto com diferentes bases científicas. 

{

  "task": "query_generation",

  "context": {
    "topic": "Diabetes tipo 2",

7. Padrão de instruções por API

Cada plataforma terá especificações próprias, separadas das regras gerais de geração. 

database: PubMed

syntax:
  boolean_operators:
    - AND
    - OR
    - NOT

  field_tags:
    - "[Title/Abstract]"
    - "[MeSH Terms]"
    - "[Author]"

rules:
  - Agrupar sinônimos com OR
  - Combinar conceitos com AND
  - Utilizar MeSH quando apropriado
  - Não inventar descritores
  - Validar a sintaxe antes de entregar

9. Atualização das especificações

O sistema deverá possuir um processo de monitoramento das documentações oficiais das APIs.

  1. Verificar alterações na documentação.
  2. Identificar mudanças em operadores, campos e filtros.
  3. Atualizar as especificações YAML.
  4. Gerar novos exemplos de treinamento.
  5. Validar os exemplos contra a API real.
  6. Treinar e avaliar o modelo.
  7. Publicar um novo checkpoint quando aprovado.

A atualização das regras operacionais e a atualização dos pesos serão processos independentes, mas coordenados.

12. Avaliação e qualidade

O modelo será avaliado por:

  • Correção sintática das strings.
  • Aderência ao contexto apresentado.
  • Cobertura dos conceitos da pesquisa.
  • Compatibilidade com a API de destino.
  • Diversidade e relevância das consultas.
  • Retenção dos conhecimentos anteriores.
  • Estabilidade após sucessivas atualizações.

Sempre que possível, as consultas serão executadas em ambiente de teste nas APIs reais, com comparação dos resultados obtidos.

Modelo: Qwen2.5-0.5B Base

Framework: Apple MLX / MLX-LM

Linguagem: Python

Treinamento: Full Fine-tuning / SFT

Aprendizado: Incremental, com replay de exemplos

Persistência: Checkpoints versionados

Arquitetura: Um único modelo especializado em múltiplas APIs

Execução: Local no MacBook M4
